# Model Card — Transaction Risk Model

## Intended use

This model is intended to rank transactions by fraud risk and support alert prioritisation. It is not intended to make fully automated financial decisions without human review, governance, and additional production controls.

## Data

Default development data uses the PaySim transaction dataset or the synthetic sample generated by this repository.

## Features

The model uses transaction-level, temporal, entity-level, and graph-derived features.

## Evaluation

Evaluation should use temporal splits. Main metrics are PR-AUC, ROC-AUC, precision@K, recall@K, and fraud value captured.

## Limitations

- PaySim is synthetic and may not represent all real fraud behaviours.
- Historical fraud labels may be delayed or incomplete in real systems.
- Fraud patterns are non-stationary and require monitoring.
- Thresholds should be selected according to review capacity and business cost.

## Monitoring

Recommended monitoring includes:

- alert volume
- fraud capture rate
- precision at operational review capacity
- feature drift
- score distribution drift
- delayed label performance
